**① 项目描述**
为某医药企业 SRM（供应商关系管理）系统打造面向供应商侧的智能问答助手，将 12MB 业务蓝图（V5.0，含 8 大模块 / 25 子流程 / 5 类附录）转化为"系统怎么用"的自然语言解答，以 iframe 嵌入供应商门户。核心痛点：蓝图篇幅大、流程码（`QS_SRM_*`）与附录交叉引用复杂，人工查文档效率低、易出错。

## 三、面试话术

### 被问「这是 Agent 吗？」
坦诚——「产品叫智能问答助手，技术核心是**检索增强生成（RAG）**，目前是只读问答、不调业务接口；如果要升级成 Agent，会加工具调用与多步闭环。」

### 为什么用 RAG 而非微调？
业务蓝图频繁变更、需可溯源、成本低、上线快；RAG 把「知识」与「模型」解耦。

### 中文检索怎么做的（重点）？
生产链路是 **稠密向量（BGE/M3E 本地模型）+ BM25 关键词 + RRF 融合**：用 BGE 把问题和文档编码成向量做语义召回，BM25 补关键词命中，RRF 把两路排序融合；再用 **bge-reranker-v2-m3 交叉编码器**对候选精排。这是 RAG 主流做法，比纯关键词检索召回更准、比纯向量检索更稳。TF-IDF 仅作无模型时的本地兜底。

### 召回遇到过什么坑？
纯融合下"流程正文会压过关键附录"，导致附录类问题召回不准。我做了**流程感知附录提权**（同流程附录随正文浮现）+ **意图关键词加权**（问题指向"报表/材料/接口"时对该类附录提权），把附录命中率提到 83%（结合 bge-reranker-v2-m3 精排后进一步提升）。——这一条最能经住追问。

### iframe 嵌入怎么保证安全？
供应商侧嵌入，做了 JWT/RBAC 鉴权、服务级 Key、父域白名单（防恶意站点套用）、限流。
